# Contributing

Contributions are welcome through issues and pull requests.

1. Create a separate directory under `skills/<skill-name>/` for each skill.
2. Add a `SKILL.md` with valid YAML frontmatter (`name`, `description`) and actionable Markdown instructions.
3. Keep the workflow focused, explain safeguards, and avoid unnecessary supporting files.
4. Validate the skill on a temporary Git repository or another safe test project before opening a pull request.
5. Document the new skill in both `README.md` and `README.id.md`.
6. Keep pull requests focused on one logical change, and do not include secrets or private data.

Use Conventional Commit subjects where practical, such as `feat(skills): add release-notes` or `docs: clarify installation`.
